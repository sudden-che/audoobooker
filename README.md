# Audiobooker

Audiobooker - это инструмент на Python для создания аудиокниг из файлов `.txt`, `.fb2` и `.pdf`.

## Основные возможности
- **Edge TTS (внешний сервис):** синтезирует речь через сервис Microsoft Edge. Локальная LLM не устанавливается и не используется.
- **Поддержка форматов:** Прямое чтение `.txt` и извлечение текста из `.fb2` и `.pdf`.
- **Разбивка на чанки:** Текст автоматически делится на части для стабильного синтеза.
- **Склейка:** Автоматическое объединение частей в один файл с помощью `ffmpeg`.
- **Подготовка текста под аудиокнигу:** проект автоматически нормализует реплики, заголовки глав, частые символы (`№`, `%`, `§`, валюты, дроби, градусы) и сохраняет абзацы для естественных пауз.
- **Точные паузы:** тег `[[PAUSE: 5000]]` добавляет в аудио 5 секунд тишины.
- **Интерфейсы:** CLI (командная строка), Telegram-бот и Web-интерфейс.

## Установка

### 1. Системные зависимости:
Для склейки аудио и создания точных участков тишины требуется `ffmpeg`.

### 2. Python зависимости:

Требуется Python 3.10 или новее; рекомендуемая версия — Python 3.12.

```bash
pip install -r requirements.txt
```
*Зависимости для бота и веб-интерфейса:* `pip install -r requirements-tg.txt` или `pip install -r requirements-web.txt`.

Если вы обновляетесь со старой версии с локальным движком, создайте новое
виртуальное окружение вместо установки поверх старого. Старый кэш модели можно
удалить вручную, если он больше не используется другими проектами. Новая
установка Audiobooker локальные модели и их зависимости не загружает.

### 3. Актуальность Edge TTS
При новой установке ставится свежая совместимая версия `edge-tts` из ветки `7.x`, не ниже `7.3.1`.

Проверить/обновить вручную:
```bash
python tts_dependency_manager.py
python tts_dependency_manager.py --apply
```

Для автопроверки на старте:
- `CHECK_TTS_DEPS_ON_START=true` — проверить наличие новой версии.
- `AUTO_UPDATE_TTS_DEPS=true` — автоматически обновить `edge-tts` перед запуском приложения.

В Docker по умолчанию `AUTO_UPDATE_TTS_DEPS=false`: зависимости устанавливаются
при сборке образа. Проверка на старте только сообщает о доступном обновлении.

#### Ошибка синтеза 403 (`Invalid response status`)

403 при подключении к `speech.platform.bing.com` означает отказ сервиса синтеза
Microsoft. Одна из причин — устаревшая `edge-tts` внутри работающего контейнера.
Например, запрос с `Sec-MS-GEC-Version=1-143.0.3650.75` использует старый протокол;
версия `7.3.1` использует `2-143.0.3650.75` и обновлённое вычисление `Sec-MS-GEC`.
Вручную менять параметры протокола не требуется — обновите библиотеку целиком.

Проверьте версию в работающем контейнере на сервере бота:

```bash
docker compose exec -T audiobooker-both python -c 'from importlib.metadata import version; print(version("edge-tts"))'
```

Требуется версия не ниже `7.3.1`. После доставки изменения в `main` существующий
CI собирает и развёртывает новый образ. Изменение `requirements.txt` обновляет
слой установки зависимостей Docker. Если контейнер обновляется вручную,
дождитесь успешной публикации образа и выполните на сервере:

```bash
docker compose pull audiobooker-both
docker compose up -d --force-recreate audiobooker-both
docker compose exec -T audiobooker-both python -c 'from importlib.metadata import version; print(version("edge-tts"))'
```

Обычный `docker compose restart` не заменяет образ и установленные зависимости.
Проверьте короткий синтез из того же контейнера и декодирование полученного MP3:

```bash
docker compose exec -T audiobooker-both python -m edge_tts --voice ru-RU-SvetlanaNeural --text 'Проверка синтеза речи.' --write-media /tmp/edge-tts-check.mp3
docker compose exec -T audiobooker-both ffmpeg -v error -i /tmp/edge-tts-check.mp3 -f null -
docker compose exec -T audiobooker-both rm -f /tmp/edge-tts-check.mp3
```

Затем повторно отправьте боту исходный текст или файл и проверьте полученное
аудио. Если 403 сохраняется с актуальной библиотекой, проверьте системное время
и синхронизацию NTP на сервере, а также доступ к `speech.platform.bing.com:443`
из контейнера, включая настройки прокси и возможные ограничения сервиса для IP
сервера. Обновление библиотеки не гарантирует устранения сетевой блокировки.

### 4. Retry для Edge TTS
Для временных сетевых ошибок `speech.platform.bing.com:443` проект теперь повторяет синтез отдельного чанка автоматически.

Настройки:
- `EDGE_TTS_MAX_RETRIES=3` — число повторов после первой неудачной попытки.
- `EDGE_TTS_RETRY_BASE_DELAY=1.5` — базовая задержка в секундах.
- `EDGE_TTS_RETRY_MAX_DELAY=12.0` — верхний предел задержки.

## Использование (CLI)

Запуск:
```bash
python audiobooker.py book.txt --voice ru-RU-SvetlanaNeural --rate +18%
```

**Все аргументы:**
- `path`: путь к одному `.txt`/`.fb2`/`.pdf` файлу или к каталогу с такими файлами.

PDF можно отправить также через Web-интерфейс или Telegram-бота. Страницы читаются
по порядку. PDF должен содержать текстовый слой: для скана без текста сначала
нужно выполнить OCR. PDF с парольной защитой не поддерживаются.
- `--voice`: голос Edge TTS.
- `--rate`: скорость речи Edge TTS, например `+18%`.
- `--chunk-size`: количество символов в одном фрагменте (дефолт 10000).
- `--max-concurrent-tasks`: количество параллельных задач синтеза.
- `--max-concurrent-files`: количество одновременно обрабатываемых книг.
- `--output-dir`: папка для сохранения.
- `--ffmpeg`: путь к исполняемому файлу `ffmpeg`.
- `--skip-chunks`: не пересобирать уже существующие фрагменты.
- `--skip-merge`: не склеивать фрагменты в один файл.

При наличии `PAUSE`-тегов режим `--skip-chunks` автоматически отключается:
вставка паузы меняет номера последующих чанков, поэтому старый кэш нельзя
безопасно переиспользовать.

## Управляющие теги паузы

Чтобы добавить точную тишину между фрагментами, вставьте в исходный текст тег:

```text
Первая часть.
[[PAUSE: 5000]]
Вторая часть.
```

Число задаёт длительность в миллисекундах: `5000` мс = 5 секунд. Имя тега не зависит от регистра, а пробелы вокруг имени, двоеточия и значения необязательны. Например, `[[pause:5000]]` и `[[ PaUsE : 5000 ]]` равнозначны.

Правила:
- значение должно быть положительным целым числом миллисекунд;
- соседние теги складываются: `[[PAUSE: 1000]][[pause: 2000]]` дают 3 секунды тишины;
- некорректный `PAUSE`-тег вызывает ошибку, и задание синтеза не запускается;
- синтаксис одинаково работает в CLI, Web-интерфейсе и Telegram-боте;
- один тег не может превышать `MAX_PAUSE_MS=600000` (10 минут);
- суммарная длительность пауз в одном задании не может превышать `MAX_TOTAL_PAUSE_MS=3600000` (60 минут).

Лимиты можно уменьшить через переменные окружения `MAX_PAUSE_MS` и `MAX_TOTAL_PAUSE_MS`. Увеличивайте их только с учётом размера выходного файла и времени обработки.

## Telegram-бот

Бот использует внешний Edge TTS. Настройки задаются через переменные окружения.

**Запуск:**
```bash
export BOT_TOKEN="your_token"
python tg_audiobooker.py
```
В боте доступна команда `/settings` для интерактивной настройки голоса, скорости и параметров синтеза.
Для параллельной обработки можно настроить:
- `MAX_CONCURRENT_REQUESTS` — сколько запросов синтеза выполнять одновременно.
- `MAX_CONCURRENT_UPDATES` — сколько Telegram-апдейтов разбирать параллельно.
- `FORWARD_GROUP_DEBOUNCE_SECONDS` — окно группировки пересланных сообщений перед запуском обработки (по умолчанию `5.0` сек).
- Для слабого сервера с 2 CPU разумный старт: `MAX_CONCURRENT_TASKS=8`, `MAX_CONCURRENT_REQUESTS=2`, `MAX_CONCURRENT_UPDATES=4`.

### Доставка больших файлов

Telegram Bot API ограничивает размер загружаемого аудио. Для больших
результатов доступна временная HTTP-ссылка:

```bash
export DELIVERY_MODE=auto
export TELEGRAM_SAFE_UPLOAD_BYTES=51380224
export DOWNLOAD_DIR=/app/data/downloads
export DOWNLOAD_TTL_MINUTES=15
export DOWNLOAD_SERVER_PORT=43561
export PUBLIC_DOWNLOAD_BASE_URL=http://server.example.org:43561
```

- `telegram` — всегда отправлять файл через Telegram;
- `send_link` — всегда публиковать временную ссылку;
- `auto` — отправлять обычные файлы через Telegram, а слишком большие — ссылкой.

Ссылка `GET /d/{token}` действует `DOWNLOAD_TTL_MINUTES` минут. Если минуты не
заданы, используется `DOWNLOAD_TTL_SECONDS`. Временный download-сервер
запускается после создания ссылки и останавливается, когда активных ссылок не
остаётся.

## Веб-интерфейс

Запустите и откройте `http://localhost:8000`:
```bash
python web_audiobooker.py
```
В интерфейсе можно выбирать голос Edge TTS и настраивать скорость и параметры обработки.

## Docker

Проще всего запустить проект через Docker Compose:

1. Скопируйте `.env.example` в `.env` и укажите `BOT_TOKEN`.
2. Запустите сервис:
```bash
docker compose up -d audiobooker-both
```

Для временных ссылок compose публикует порт `43561`. Перед облачным развёртыванием
укажите внешний адрес в `PUBLIC_DOWNLOAD_BASE_URL`.

## Очистка текста
Скрипт `clean.py` позволяет предварительно очистить текст от типичного "мусора" перед синтезом.

FB2 и PDF файлы обрабатываются автоматически внутри `audiobooker.py`, внешние конвертеры не требуются.

## Best Practices для аудиокниг
- Держите абзацы и пустые строки: они дают естественные паузы лучше, чем ручные повторы знаков препинания.
- Для `Edge TTS` разумный старт: `VOICE=ru-RU-SvetlanaNeural`, `SPEED=+10%` ... `+18%`.
- Для точной длительности тишины используйте `[[PAUSE: миллисекунды]]`.
- Если в исходнике много служебных символов, списков и формул, сначала прогоняйте текст через встроенную предобработку проекта или `clean.py`.

## Имена файлов
- Архивы, чанки и итоговые файлы теперь получают имя от исходного файла, а не от временного `uploaded`.
- Кириллица автоматически транслитерируется в ASCII, чтобы имена стабильно открывались в браузере, Docker и Telegram.
- Длина basename ограничивается переменной `OUTPUT_BASENAME_MAX_LENGTH` (по умолчанию `48`).
